# tor-connect

Один исполняемый файл для Windows (цель: от Windows 7 SP1 и Server 2008 R2), внутри которого **в одном процессе**
работает свежий Tor. Без дочерних процессов, без отдельных плагинов, без установщика.
Все настройки, включая обычные настройки Tor, вышестоящие прокси и мосты, лежат в **одном файле `tecon.cfg`**.

> **Статус: ранняя разработка.** Работает запуск Tor 0.4.9 в одном процессе на Windows 7 и 10, единый файл настроек,
> вышестоящие прокси с перебором и применение изменений файла на лету. В работе: транспорты obfs4 и webtunnel
> в том же процессе, перебор мостов, GeoIP, служба Windows, входящий прокси с паролем (SOCKS5 и HTTP на одном порту).
> Подробнее в [docs/PLAN.md](docs/PLAN.md).

## Быстрый старт

1. Скачайте `tor-connect-win64.exe` со страницы [Releases](../../releases/tag/dev-latest) (сборка `dev-latest`).
2. Запустите. Рядом появятся файл настроек `tecon.cfg` и папка данных `data`. Дождитесь `Bootstrapped 100% (done)`.
3. В программе или браузере укажите прокси **SOCKS5 `127.0.0.1:9050`** (в Firefox включите «Удалённый DNS»).
4. Остановка: `Ctrl+C` (повторное нажатие завершает принудительно).

## Файл настроек `tecon.cfg` (Tor Extended CONfig)

Это обычный `torrc`, расширенный директивами tor-connect. Всё, что не является директивой tor-connect, передаётся Tor как есть,
поэтому любой готовый `torrc` годится: достаточно назвать его `tecon.cfg`.

- **Имена файла:** `tecon.cfg`, затем `tecon` (без расширения).
- **Где ищется:** сначала рядом с `tor-connect.exe`, затем в рабочей папке. Файл рядом с программой приоритетнее
  и **полностью перекрывает** файл из рабочей папки (содержимое не объединяется). Если файла нет нигде, создаётся `tecon.cfg`
  рядом с программой (если там нельзя писать, то в рабочей папке).
- **Явный файл:** `tor-connect.exe -f путь\к\файлу` или просто `tor-connect.exe путь\к\файлу` (если файла нет, он создаётся).
- **На лету:** файл перечитывается автоматически. Изменения применяются без перезапуска, кроме тех, что Tor не позволяет менять
  на ходу (например, `DataDirectory`): о них программа сообщит в журнале. Если новый файл содержит ошибку, остаются прежние настройки.

### Директивы tor-connect

| Директива | Значение |
|---|---|
| `Upstream` | вышестоящий прокси для самого Tor: `direct`, `socks5://[логин:пароль@]хост:порт` или `http://[логин:пароль@]хост:порт`. Строк может быть несколько: они перебираются по порядку, последний рабочий пробуется первым, сбойный на 30 секунд уходит в конец. `direct` означает прямое подключение. |

Специальные символы в логине и пароле записываются в процентном виде: `@` → `%40`, `#` → `%23`, `:` → `%3A`, `/` → `%2F`.
Директивы Tor `Socks5Proxy`, `HTTPSProxy` и связанные с ними заменены на `Upstream` и в файле игнорируются.

### Полный пример `tecon.cfg`

Этот пример совпадает с файлом, который программа создаёт по умолчанию (совпадение проверяется тестом).

<!-- TECON-EXAMPLE:BEGIN -->
```text
# ==============================================================================
#  tecon.cfg — Tor Extended CONfig: единый файл настроек tor-connect
# ==============================================================================
#  Это обычный файл настроек Tor (torrc), расширенный директивами tor-connect.
#  Любая строка, которая не является директивой tor-connect, передаётся Tor как
#  есть, поэтому подойдёт любой готовый torrc: достаточно назвать его tecon.cfg.
#
#  Комментарий начинается с «#» в начале строки или после пробела.
#
#  Где ищется файл (имена по порядку: tecon.cfg, tecon):
#    1. рядом с tor-connect.exe;
#    2. в рабочей папке (откуда запущена программа).
#  Файл рядом с программой приоритетнее и полностью перекрывает файл из рабочей
#  папки (настройки не объединяются). Если файла нет нигде, создаётся этот.
#  Указать файл явно можно так:  tor-connect.exe -f путь\к\файлу
#
#  Файл перечитывается на лету: сохранили, и изменения применились. Если
#  настройку нельзя поменять без перезапуска (например, DataDirectory),
#  программа сообщит об этом. При ошибке в новом файле продолжают действовать
#  прежние настройки.
# ==============================================================================

# ------------------------------------------------------------------------------
#  1. Входящий прокси (SOCKS5) для ваших программ и общие параметры Tor
# ------------------------------------------------------------------------------
# Локальный SOCKS5-прокси. Адрес 127.0.0.1 означает «только этот компьютер».
SocksPort 127.0.0.1:9050

# Журнал в окно программы (уровни: notice, info, debug). В файл:
# Log notice file D:\tor\tor.log
Log notice stdout

# Каталог данных Tor. По умолчанию это папка data рядом с программой.
#DataDirectory D:\tor\data

# Страна выхода (нужны файлы GeoIP, их будет скачивать команда -geo-update):
#ExitNodes {de},{nl}
#StrictNodes 1

# ------------------------------------------------------------------------------
#  2. Вышестоящие прокси для самого Tor (необязательно)
# ------------------------------------------------------------------------------
# Tor выходит в интернет через эти прокси. Строк может быть несколько: варианты
# перебираются по порядку, последний рабочий пробуется первым, а сбойный на время
# уходит в конец очереди. «direct» означает прямое подключение без прокси.
# Форматы: direct | socks5://[логин:пароль@]хост:порт | http://[логин:пароль@]хост:порт
# Ключ командной строки -upstream заменяет все строки Upstream из этого файла.
#Upstream direct
#Upstream socks5://user:pass@10.0.0.1:1080
#Upstream http://user:pass@10.0.0.2:8080

# ------------------------------------------------------------------------------
#  3. Мосты (если Tor блокируют)
# ------------------------------------------------------------------------------
# Сейчас поддерживаются обычные мосты без транспорта (IP:порт ОТПЕЧАТОК).
# Транспорты obfs4 и webtunnel, а также перебор и проверка мостов в разработке.
#UseBridges 1
#Bridge 203.0.113.10:443 0123456789ABCDEF0123456789ABCDEF01234567
```
<!-- TECON-EXAMPLE:END -->

## Командная строка

| Ключ | Действие |
|---|---|
| *(без аргументов)* | найти или создать `tecon.cfg` и запустить Tor |
| `-f файл`, `-c файл` или просто `файл` | использовать указанный файл настроек |
| `-upstream адрес` | вышестоящий прокси (можно несколько раз, порядок важен). Заменяет все строки `Upstream` из файла и не меняется при перезагрузке файла. |
| `--version`, `--help` | передаются Tor, файлы не создаются |

Пример: `tor-connect.exe -upstream direct -upstream socks5://user:pass@host:1080 -upstream http://user:pass@host:8080`

## Безопасность

- По умолчанию прокси слушает только `127.0.0.1`. Адрес `0.0.0.0` открывает его для всей сети **без пароля**: используйте только в доверенной сети.
- Не публикуйте свои мосты и файл `tecon.cfg` с паролями: чем больше людей знает мост, тем быстрее его блокируют.
- Tor не позволяет сократить цепочку: путь всегда из трёх узлов. Проект этого не меняет и не обещает анонимности лучше, чем Tor Browser.
- Windows 7 и Server 2008 R2 не получают обновлений безопасности от Microsoft; использование на ваш риск.

## Сборка

Всё собирается на GitHub Actions (workflow `build-win`): Tor, OpenSSL, libevent и zlib собираются статически кросс-компилятором mingw-w64
(классическая `msvcrt`, без UCRT), затем Go 1.20 (последний с поддержкой Windows 7) линкует их в один exe. Версии и хэши зависимостей
закреплены в `scripts/versions.env`. Локальная сборка не требуется.

| Путь | Назначение |
|---|---|
| `cmd/tor-connect` | точка входа, встраивание Tor через cgo, ресурсы exe (иконка, манифест) |
| `internal/tecon` | разбор `tecon.cfg`, поиск и создание файла |
| `internal/app` | запуск, генерация `torrc`, перезагрузка настроек на лету |
| `internal/tcontrol` | клиент управляющего протокола Tor |
| `internal/upstream`, `internal/socks5` | вышестоящие прокси с перебором, SOCKS5 |
| `internal/ptargs` | параметры транспортов |
| `scripts/` | сборка зависимостей, генерация иконки |

## Лицензия и товарные знаки

Лицензия будет выбрана после проверки совместимости лицензий всех компонентов (Tor, OpenSSL, libevent, zlib и др.);
список сторонних компонентов появится в `THIRD_PARTY.md`. Проект не связан с Tor Project и не одобрен им.
