# План работ

## M0. Проба (текущий этап)
- Свежий Tor (0.4.9.x) + OpenSSL 3.5 LTS + libevent + zlib собираются статически под Windows x64 (mingw-w64, msvcrt).
- Go 1.20 (последний с поддержкой Windows 7) линкует их через cgo; Tor запускается внутри процесса (`tor_api.h`).
- Проверка на Windows 7 SP1 без обновлений: `probe-win64.exe --version`, затем запуск с `torrc` и подключение к сети.
- Критерий успеха: бинарник запускается на голой Win7 и доходит до `Bootstrapped 100%`.

## M1. Лаунчер
- Конфиг, служба Windows (автоперезапуск при сбое), SOCKS5 + HTTP на одном порту, onion-сервисы с клиентской авторизацией.
- Разбор команд: `-geo-update [дни]`, `-test-bridges`, `-service …`; комбинируются слева направо.
- GeoIP/GeoIPv6 скачиваются и обновляются самой программой (зеркала: GitLab Tor Project и копия в этом репозитории).

## M2. Транспорты в том же процессе
- obfs4 и webtunnel как горутины, подключённые к Tor как неуправляемые транспорты (`ClientTransportPlugin … socks5 …`).
- Проверка мостов на Go (рукопожатие), смена мостов на лету через контрольный порт.

## M3. Автообновление мостов
- Сборщик на Actions по расписанию → подписанный список (ed25519) → несколько зеркал.
- Клиент: проверка подписи, кэш на диске, встроенный запасной список, проверка достижимости на месте.

## M4. Snowflake, документация, релизы
- Snowflake в том же процессе; инструкции; подписанные релизы; регулярный автобэкап.

## Риски
- Tor — не библиотека «из коробки»: возможны проблемы со статической линковкой и перезапуском в процессе.
- Windows 7: свежие Tor/OpenSSL могут использовать API, которых там нет; проверяется на реальной машине.
- Go 1.20 фиксирует зависимости Go-кода (obfs4, Snowflake) на версиях, совместимых с ним.
